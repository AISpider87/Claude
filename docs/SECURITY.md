# SECURITY — checklist OWASP Top 10 e controlli in essere

Verificata alla consegna v1 (2026-09-09). Da rileggere a ogni milestone.

| Rischio (OWASP 2021)               | Controllo in SuperLega                                                                                                                                                                                                                                                                                                                 |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A01 Broken access control          | RLS su **tutte** le tabelle; scritture di dominio solo via funzioni `security definer` che rivalidano ruolo, proprietà della squadra, stato sessione e limiti; `private.require_admin()` in ogni funzione admin; route `/api/admin/export` con controllo utente/attivo/admin; test SQL per anon/manager/admin (`tests/db/*.test.sql`). |
| A02 Cryptographic failures         | Solo HTTPS (Vercel/Supabase); password gestite da Supabase Auth (bcrypt); nessun segreto nel repo (`.env.example` con placeholder); `SUPABASE_SERVICE_ROLE_KEY` usata solo nel cron server-side.                                                                                                                                       |
| A03 Injection                      | Nessun SQL costruito da stringhe; parametri tipizzati nelle funzioni; Zod su ogni input dei server action; nomi/note renderizzati da React (escape automatico); email HTML con escape esplicito.                                                                                                                                       |
| A04 Insecure design                | Regole di dominio nel database (non aggirabili via API); registro operazioni append-only; annullamento = operazione inversa; guardie di sessione; limiti di rate definiti lato server.                                                                                                                                                 |
| A05 Security misconfiguration      | `search_path` fissato in ogni funzione; grant espliciti (`revoke all … from public`); `email` dei profili con grant di colonna solo admin; bucket Storage con policy admin; `Cache-Control: no-store` sugli export.                                                                                                                    |
| A06 Vulnerable components          | Dipendenze aggiornate (Next 16, Supabase JS 2, exceljs al posto di SheetJS con CVE note); `npm audit` in CI da attivare in M8+ (`npm audit --omit=dev`).                                                                                                                                                                               |
| A07 Identification & auth failures | Verifica email obbligatoria; recupero password con `token_hash`; codice lega applicato nel trigger di signup; rate limiting su login (10/15 min per indirizzo+email), registrazione e recupero (5/ora per indirizzo) oltre ai limiti di Supabase Auth; messaggi che non rivelano se un'email esiste.                                   |
| A08 Software & data integrity      | Migrazioni versionate e immutabili; import con anteprima e conferma, guardia anti-svuotamento del listone; CI (lint, typecheck, test, build, e2e, test DB) su ogni push.                                                                                                                                                               |
| A09 Logging & monitoring           | `audit_log` append-only (login-side: azioni; operazioni; azioni admin) visibile in _Admin → Audit log_; log import e notifiche; esiti cron in `imports`.                                                                                                                                                                               |
| A10 SSRF                           | Il sync quotazioni scarica solo dall'URL configurato dall'admin in env (non da input utente), con timeout, limite 5 MB e controllo del tipo di file; il client Resend usa un endpoint costante.                                                                                                                                        |

## Segnalazioni

Chi trova un problema lo comunica all'admin della lega in privato; l'admin
apre una issue privata o corregge sul branch. Nessun dato personale oltre a
email e nome visualizzato è trattato dall'app.
